# ProChat Brand Ruleset

**Status:** canonical copy rules  
**Owner:** Steve Westhoek  
**Last updated:** 2026-06-05

## Core message

```text
ProChat helps your team turn messy work into useful outputs ready for review.
```

## Brand voice

Use language that is:

- simple
- practical
- direct
- buyer-focused
- outcome-first
- calm
- specific

Avoid language that is:

- technical first
- hype-driven
- abstract
- vague
- guru-like
- too strategic for a buyer

## Buyer language to use

Use phrases like:

- stop rewriting the same work
- stop re-explaining the same context
- reply faster
- prepare better drafts
- turn messy notes into clear next steps
- make handoffs clearer
- keep useful knowledge reusable
- prepare work for human review
- use your own examples and style
- save time on repeated work

## Internal terms to avoid in public marketing

Do not lead public pages with:

- Work Memory
- work brain
- infinite brain
- second brain
- operating system
- modules
- knowledge graph
- runtime
- connectors
- routing
- model selector
- CLI
- architecture
- installable
- autonomous employee

These can exist internally, but buyers should first see the pain and outcome.

## Before/after rule

Every marketing page should quickly show:

Before:

```text
messy input, repeated explanation, manual rewriting, slow follow-up
```

After:

```text
drafts, summaries, task lists, reports, replies, and next steps ready for review
```

## Offer clarity rule

Every offer should answer:

1. What repeated task is painful?
2. What messy input does the buyer already have?
3. What useful output will ProChat prepare?
4. Who reviews it?
5. How does this save time?

## CTA rules

Good CTAs:

- Show us one repeated task
- Book a time-saving call
- See what ProChat can prepare
- Get a review-ready example

Avoid CTAs that require understanding the system:

- Explore the OS
- Configure a module
- Build a workflow runtime
- Install ProChat OS

## Proof rule

Proof should be visual and practical.

Show:

```text
input → output → review
```

Do not show architecture unless the audience is technical.
