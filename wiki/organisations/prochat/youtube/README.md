## YouTube content lanes

Every approved video must belong to exactly one lane:

```text

```

Use YouTube to support:

- QA domain credibility;
- selected beta demonstrations;
- evidence-based testing discussions;
- local memory workflows;
- sanitization and client-data boundaries;
- tester onboarding and feedback;
- case-study learning from real repeated investigations.

### Lane 2 — ProChat Workbench

Use YouTube to support:

- qualified GitHub discovery;
- installation and onboarding;
- guarded real-project demonstrations;
- exact local context;
- bounded changes;
- targeted validation;
- explicit Git control;
- responsible tool comparisons.

## Operating rules

YouTube work must:

- select exactly one product lane per video;
- use real product capabilities, real demonstrations, or clearly labeled questions;
- preserve customer, client, employer, repository, and project privacy;
- keep customer and client memory local;
- require human review before publishing;
- avoid invented users, outcomes, testimonials, metrics, or product claims;
- avoid obsolete software-launch, commercial-growth, and generic infrastructure-course positioning;
- avoid presenting future capabilities as current products;
- avoid claiming that ProChat replaces test tools, professional judgment, editors, or all competing workflows.

## Presentation system

Approved videos should preserve:

- calm screen-share delivery;
- one bounded outcome per video;
- result-first demonstrations;
- tester-derived control insights;
- restrained editing;
- low-clutter visuals;
- honest limitations;
- evidence before conclusions.
