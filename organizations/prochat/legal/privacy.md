# ProChat Beta Privacy Notice

**Status:** internal draft for factual verification and legal review  
**Last updated:** 2026-07-02  
**Applies to:** ProChat website visitors, beta applicants, selected testers, support contacts, and feedback contributors

> This draft must be reviewed against the actual website, repository, support, analytics, cookie, email, hosting, and beta-application data flows before publication.

## 1. Controller

The intended controller is:

```text
Steve Westhoek, trading as ProChat
Porto, Portugal
Email: support@prochat.tools
```

Before publication, confirm the full legal identity, business address, registration details, and any disclosures required under Portuguese law.

## 2. Product scope

ProChat currently has exactly two products:

```text
ProChat Memory
└── current edition: ProChat Memory for QA

ProChat Workbench
```

ProChat is pre-revenue. The current focus is a free, selected, indefinite beta of ProChat Memory for QA distributed through a sanitized public repository.

## 3. Local product data

### Customer and client project memory

ProChat Memory is local-first.

Customer and client project memory remains on the user’s computer unless the user deliberately sends information to ProChat or to a third-party service.

ProChat does not host customer or client project memory as part of the current beta.

Local product data may include:

- memory workspaces;
- Markdown files;
- project notes;
- test-failure evidence;
- root causes, fixes, and reviewed lessons;
- repository context;
- local configuration;
- Git history created by the user.

ProChat does not automatically receive this local data merely because the product is installed or used.

### Workbench project data

ProChat Workbench operates against repositories, documentation, notes, and project folders on the user’s computer through bounded local operations.

The user controls which local sources and operations are exposed. ProChat does not automatically receive repository contents or local Workbench context merely because the product is used.

## 4. Information deliberately sent to ProChat

ProChat may process information a person deliberately provides through an actual, verified contact or participation channel.

Depending on the channel, this may include:

- name;
- email address;
- GitHub username or profile link;
- company or professional role;
- beta-application answers;
- support messages;
- product feedback;
- issue reports;
- sanitized logs or screenshots;
- repository links supplied by the user;
- interview notes;
- approved testimonial or case-study material;
- communication preferences.

Users must not send confidential client data, secrets, credentials, personal data, proprietary source code, or unsanitized project evidence unless ProChat has expressly requested it through an approved secure process and the user has authority to disclose it.

## 5. Beta participation data

The selected beta may require limited information to:

- assess whether an applicant is a suitable tester;
- contact selected participants;
- provide onboarding information;
- understand the participant’s QA workflow;
- collect structured product feedback;
- investigate reported product problems;
- manage participation in the feedback cohort;
- request permission for a testimonial or case study.

Selection for the feedback cohort is manual. Public access to a sanitized repository does not by itself mean that every repository visitor is a selected tester or entitled to support.

## 6. GitHub and public repository interactions

The current beta may be distributed through a sanitized public GitHub repository.

When a person views, stars, forks, watches, opens an issue, submits a pull request, or otherwise interacts with a repository, GitHub processes information under its own terms and privacy notice.

ProChat may see information made available through those interactions, such as:

- public profile information;
- username;
- issue or pull-request content;
- comments;
- commit attribution;
- repository activity visible to maintainers.

This draft does not assert that ProChat uses GitHub OAuth, collects an associated email address, or maintains private-repository access records. Add those disclosures only if the relevant features and data flows are verified.

## 7. Website and communications data

The website or communication channels may technically process limited information necessary to deliver a page, receive a message, prevent abuse, or maintain security.

Possible categories include:

- IP address;
- request time;
- browser or device information;
- page requested;
- security and error logs;
- message metadata.

Before publication, identify what is actually collected, which providers process it, the purpose, legal basis, retention period, and transfer safeguards.

Do not state that analytics, marketing email, transactional email, payment, cookie, or customer-account services are active unless their actual use has been confirmed.

## 8. Third-party services chosen by users

A user may choose to connect or use third-party services with ProChat products, including AI services, Git hosting, editors, terminals, communication tools, or cloud services.

Those services may receive information the user supplies or authorizes. Their processing is governed by their own terms and privacy notices.

Users are responsible for:

- understanding third-party data settings;
- confirming employer or client authorization;
- avoiding disclosure of confidential information;
- selecting appropriate service plans and regions;
- reviewing whether data may be retained or used by the third party;
- complying with applicable contracts and policies.

ProChat does not guarantee that information remains local after a user intentionally sends it to a third-party service.

## 9. Purposes of processing

Where applicable, ProChat may process personal data to:

- respond to enquiries;
- assess and manage beta participation;
- provide beta onboarding or support;
- receive, review, and act on feedback;
- maintain repository and community interactions;
- investigate security, abuse, or reliability problems;
- manage approved testimonials or case studies;
- comply with legal obligations;
- establish, exercise, or defend legal claims;
- improve product documentation and the beta experience using sanitized or aggregated learning.

Personal data must not be reused for an incompatible purpose without an appropriate legal basis and notice.

## 10. Legal bases

The applicable legal basis depends on the actual processing activity.

Potential legal bases may include:

- steps requested before participation or another agreement;
- performance of the Beta and Evaluation Terms;
- legitimate interests in operating, securing, and improving the beta;
- consent for optional communications, testimonials, case studies, or non-essential cookies;
- compliance with legal obligations;
- establishment, exercise, or defence of legal claims.

Consent must be freely given, specific, informed, and capable of withdrawal. Do not use consent as a generic basis where another basis applies or where consent would not be freely given.

The final public notice must map each verified purpose to its legal basis.

## 11. Sharing and processors

ProChat may share personal data only where necessary with verified service providers, professional advisers, authorities, or other recipients permitted by law.

Before publication, list each active provider and explain:

- what it does;
- which data it receives;
- why the processing is necessary;
- where the data is processed;
- the applicable transfer safeguards;
- the provider’s retention role.

This draft intentionally does not assert that Stripe, GitHub OAuth, Resend, MailerLite, Google Analytics, or any other named processor is active.

ProChat does not sell personal data.

## 12. International transfers

Some verified providers may process personal data outside the European Economic Area.

If this occurs, the final notice must identify the transfer mechanism and applicable safeguards, such as an adequacy decision or approved contractual safeguards, where required.

No provider-specific transfer claim should be published until the provider and data flow are confirmed.

## 13. Retention

Personal data should be kept only for as long as necessary for the stated purpose, legal obligations, security, dispute resolution, or defence of claims.

Before publication, define practical periods or review criteria for at least:

- unsuccessful beta applications;
- selected participant records;
- support and feedback messages;
- security logs;
- GitHub issues and contributions;
- consent records;
- approved testimonials and case studies;
- records needed for legal claims.

Where deletion is not technically possible because information forms part of a public Git history or repository discussion, explain the available correction, anonymization, or account-management options.

## 14. Security

ProChat should use reasonable technical and organizational measures appropriate to the actual data processed.

Users remain responsible for protecting their local environment, including:

- access controls;
- device and account security;
- repository permissions;
- secrets management;
- backups;
- sanitization before sharing;
- review of commands and changes;
- compliance with employer and client requirements.

No security measure can eliminate all risk.

## 15. User responsibilities for submitted material

A person submitting logs, screenshots, repositories, memory, feedback, or other material confirms that they:

- are authorized to provide it;
- have removed secrets and unnecessary personal data;
- have complied with employer and client obligations;
- understand that support and feedback channels are not a repository for customer project memory;
- will provide a corrected or deleted version when they discover an improper disclosure.

ProChat may refuse, remove, redact, or delete submitted material that appears unsafe, unlawful, confidential, or outside the beta’s purpose.

## 16. Rights

Subject to applicable law, a person may have rights to:

- access personal data;
- correct inaccurate data;
- request deletion;
- restrict processing;
- object to certain processing;
- receive portable data where applicable;
- withdraw consent without affecting earlier lawful processing;
- complain to a supervisory authority.

Requests may be sent to:

```text
support@prochat.tools
```

Before publication, verify the process for confirming identity, responding within applicable deadlines, and recording requests.

A person may also lodge a complaint with the Portuguese data-protection authority, the Comissão Nacional de Proteção de Dados (CNPD), or another competent supervisory authority.

## 17. Cookies and analytics

The final public notice must describe only cookies, analytics, or similar technologies that are actually in use.

If only technically necessary storage is used, state that accurately.

If optional analytics or marketing technologies are introduced, provide the required information and consent controls before activating them where applicable.

Browser settings alone are not a substitute for a required consent mechanism.

## 18. Children

The current products and beta are intended for adults acting in a professional or business context.

The beta is not directed to children. If ProChat learns that it has collected a child’s personal data without an appropriate legal basis, it should delete the data where required.

ProChat may update the notice when products, providers, data flows, legal requirements, or beta processes change.

The current version and effective date should be published clearly. Material changes should be communicated through an appropriate channel where required.
