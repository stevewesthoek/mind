## 3. The problem

**THE REPEATED-WORK PROBLEM**

# Important project knowledge is created—and then scattered.

It lives across conversations, tickets, logs, repositories, notes, documents, screenshots, and old investigations.

When that knowledge is not preserved in a reusable form, the next task begins with recovery work.

You search for the old conversation.

You reconstruct why a decision was made.

You repeat project context.

You look for the fix that worked last time.

You reconsider possibilities that were already ruled out.

You correct an assumption that was corrected before.

Then you begin the actual work.

**The work happened.  
The useful understanding did not remain available.**

- Decisions become readable project records.

- Approved examples remain available.
- People decide what becomes trusted memory.

- The memory can be corrected or retired when circumstances change.

## 7. The memory workflow

**HOW IT WORKS**

# Evidence becomes memory through review.

### 01 — Begin with current evidence

Useful memory begins with real project work.

A failure occurs.

A decision is made.

An example is approved.

A correction is accepted.

A source changes the conclusion.

A reviewer explains why something should be handled differently.

The current evidence comes first.

### 02 — Draft a reusable lesson

AI assistance may help identify a possible pattern or prepare a draft record.

The draft can describe:

- What happened
- What evidence mattered
- What was ruled out
- What was decided
- Where the lesson applies
- What should be checked next time

A draft is not trusted memory.

### 03 — Sanitize and scope it

Project knowledge should not automatically become client-wide, team-wide, or cross-project memory.

Sensitive details should not be promoted into reusable memory.

The record must have a clear scope.

Possible scopes include:

- Personal
- Project
- Client
- Team
- Organization
- Cross-project

Promotion to a broader scope requires sanitization, review, and an explicit decision.

### 04 — Review it

A person reviews the draft.

Approve it.

Edit it.

Clarify it.

Reject it.

Or keep it as unreviewed material.

Human approval is required before a draft becomes trusted memory.

### 05 — Retrieve it when relevant

The complete memory workspace may contain many records.

The current task should receive only the memory relevant to its project, scope, and question.

The system should make it possible to see which memory influenced an AI-assisted result.

### 06 — Improve or retire it

Memory is maintained over time.

It can be corrected.

Improved.

Split.

Merged.

Or retired when it no longer applies.

**Current evidence and human judgment remain stronger than stored memory.**

## 9. The trust model

**REVIEW-FIRST**

# AI may propose. People decide.

ProChat does not treat every note, log, conversation, or AI-generated draft as trusted memory.

The trust workflow is explicit:

**Raw evidence**

↓

**Draft lesson**

↓

**Sanitization**

↓

**Human review**

↓

**Approved, scoped memory**

Unreviewed input must not silently become trusted memory.

A plausible AI interpretation is not automatically a project fact.

Review determines:

- Whether the record is accurate
- Whether the source supports it
- Whether the scope is correct
- Whether confidential details have been removed
- Whether newer evidence has changed the conclusion
- Whether the record should be approved, edited, rejected, or retired

Review is not a secondary feature.

Review is what makes memory reusable with confidence.

## 10. The evidence hierarchy

**CURRENT EVIDENCE COMES FIRST**

# Memory should guide the work—not overrule reality.

Stored memory is useful because it carries previous understanding forward.

But previous understanding can become incomplete or outdated.

ProChat follows a clear evidence hierarchy:

**Current evidence and human judgment**

is stronger than

**Reviewed stored memory**

which is stronger than

**Unreviewed notes or AI drafts**

Fresh logs, traces, source code, screenshots, test output, changed requirements, and professional judgment can override an older memory.

The correct response to conflicting evidence is not blind reuse.

It is investigation, review, and improvement of the memory.

## 11. Local ownership

**LOCAL-FIRST**

# Customer memory remains on the customer’s computer.

ProChat Memory is designed around a customer-owned memory workspace.

The recommended separation is:

**Product repository**

**Customer-owned memory workspace**

**Customer or client project repository**

ProChat does not host the memory workspace, project evidence, client data, or approved lessons in the current product model.

The initial product is installed and run locally.

The memory workspace should not be stored inside a public product repository.

Sensitive memory must not be pushed to a public Git repository.

## 12. Markdown-first memory

**READABLE BY DESIGN**

# Durable memory should not become an opaque system state.

Where practical, durable memory is represented in readable Markdown files.

Markdown helps keep memory:

- Inspectable
- Editable
- Portable
- Searchable
- Reviewable
- Compatible with Git
- Useful across supported AI tools

Structured metadata and indexes may improve retrieval.

They should not make the source memory unreadable or opaque.

## 13. Git-compatible history

**OPTIONAL VERSION CONTROL**

- Reviewable differences

- Controlled organizational sharing

Git is not required to understand the memory.

It is an optional way to make important changes versionable and reviewable.

## 16. Measuring repeated work

**MEASURE BEFORE CLAIMING**

# How much time goes into rebuilding project context?

ProChat does not promise a universal number of hours saved.

Different people repeat different amounts of investigation, explanation, searching, and correction.

Measure the baseline first.

### Illustrative input

**People doing repeated AI-assisted project work**  
5

**Context rebuilds per person per day**  
2

**Average minutes spent per rebuild**  
12

**Working days per month**  
20

### Illustrative baseline

5 people × 2 rebuilds × 12 minutes × 20 days

# 40 hours per month

This is a model based on example inputs.

It is not a measured ProChat result.

### Before a pilot

Record the actual time spent:

- Searching previous work
- Reconstructing project background
- Repeating corrections
- Rechecking previously eliminated causes
- Locating approved examples
- Explaining established constraints

### After a pilot

Measure the same workflow again.

For example:

**Measured baseline**  
40 hours

**Measured after value**  
30 hours

**Measured difference**  
10 hours, or 25%

The after value must come from actual use.

It should never be inserted as a promised product outcome.

## 22. FAQ

### What is ProChat?

ProChat is a memory-first software company.

It builds local products that keep project knowledge reusable and connect familiar AI interfaces to real project work.

### How many products does ProChat have?

Two:

- ProChat Memory
- ProChat Workbench

### What is ProChat Memory?

ProChat Memory is the flagship product.

It is a local, Markdown-first project memory system for capturing, reviewing, retrieving, and improving reusable project knowledge.

### Who can use ProChat Memory today?

The first and only current discipline-specific edition is ProChat Memory for QA.

The current primary user is an individual QA tester.

### Is ProChat Memory a chatbot?

No.

It is the project-memory layer around AI-assisted work rather than a replacement conversational interface.

### Is it the same as chat history?

No.

Chat history preserves conversations.

ProChat Memory preserves reviewed knowledge intended to remain useful across later work.

### Does ProChat automatically trust everything an AI identifies?

No.

Raw evidence and AI-generated drafts are not trusted memory.

Human approval is required before a draft becomes approved memory.

### What happens when stored memory conflicts with current evidence?

Current evidence and human judgment take priority.

Stored memory should guide an investigation, not overrule fresh evidence.

### Where is the memory stored?

The current product model stores customer memory on the customer’s own computer in a local memory workspace.

ProChat does not host the memory workspace, project evidence, client data, or approved lessons.

### Is the memory portable?

Readable Markdown is used where practical so memory remains inspectable, editable, searchable, Git-compatible, and portable.

### Can memory be changed?

Yes.

The canonical memory lifecycle supports later correction or retirement.

The product principles also support improving, splitting, and merging memory.

### Can the workspace use Git?

A customer may commit the workspace to a private Git repository.

Sensitive memory must not be pushed to a public repository.

### Does local-first mean no information can ever reach an external AI provider?

No universal claim should be assumed.

ProChat does not host the customer’s memory workspace, but the data behavior of a compatible AI client depends on that client, its configuration, and its provider terms.

### Is ProChat Memory encrypted?

No general encryption guarantee is currently documented.

### Does ProChat Memory integrate with every AI tool?

ProChat Memory may be used through compatible AI clients.

### Is commercial pricing available?

ProChat is pre-revenue.
