# ProChat Messaging Framework

**Status:** canonical messaging framework  
**Owner:** Steve Westhoek  
**Last updated:** 2026-07-01

## Company message

ProChat is a memory-first software company.

It builds local products that keep project knowledge reusable and connect familiar AI interfaces to real project work.

## Product hierarchy

```text
ProChat
├── ProChat Memory
│   └── ProChat Memory for QA
└── ProChat Workbench
```

ProChat currently has exactly two products.

## Core philosophy

```text
Memory is the foundation.
Evidence keeps it trustworthy.
Human review improves it.
AI puts it to work.
```

## ProChat Memory

ProChat Memory is the flagship product.

Core message:

```text
Keep reviewed project knowledge reusable.
```

Supporting points:

- memory remains local;
- durable knowledge is Markdown-first where practical;
- Git can provide version history and reviewable changes;
- current evidence and human judgment override stored memory;
- unreviewed material does not automatically become trusted memory;
- ProChat does not host customer memory in the current product model.

Homepage presentation:

```text
ProChat Memory
Currently available for QA
```

## ProChat Memory for QA

Primary message:

```text
Stop solving the same QA failure twice.
```

Supporting explanation:

```text
ProChat Memory for QA helps testers preserve reviewed lessons from
failed tests and investigations so useful knowledge can be retrieved
when a similar problem appears again.
```

Use language about:

- failed tests;
- investigation evidence;
- causes and fixes;
- selectors, test data, and environments;
- reviewed lessons;
- local tester-owned memory;
- repeated usage;
- human approval;
- beta learning.

Do not describe it as a test runner, test-management suite, issue tracker, CI service, or autonomous QA system.

## ProChat Workbench

Primary message:

```text
A ChatGPT-first local builder workbench.
```

Supporting explanation:

```text
Use ChatGPT as the reasoning layer and your local computer as the
project and execution layer.
```

Supporting points:

- exact local context;
- guarded operations;
- targeted validation;
- explicit Git control;
- persistent project work through the familiar ChatGPT interface;
- support for repositories, documentation, notes, and knowledge folders.

## Competitive comparison

Workbench may be described as an alternative workflow to Cursor, Claude Code, and similar tools.

Use balanced language:

```text
ProChat Workbench offers a ChatGPT-first alternative for builders who
value the native ChatGPT experience, local project context, guarded
execution, targeted validation, and explicit Git control.
```

Do not claim:

- complete replacement of every editor;
- unlimited ChatGPT usage;
- zero hallucinations;
- guaranteed lower cost;
- greater speed in every workflow.

It is acceptable to explain that Workbench can be especially useful when a builder wants to continue using ChatGPT, work across devices, or reduce dependence on separately metered coding-agent workflows, subject to actual plan limits and product capabilities.

## Current business stage

ProChat is pre-revenue.

Both products are in active development.

Current messaging should emphasize:

- public beta status;
- selected QA beta testers;
- GitHub availability;
- real usage and feedback;
- local data ownership;
- product iteration;
- licensing still being prepared;
- monetization after evidence of retained value.

Do not imply that pricing, enterprise licensing, hosted services, or full commercial support are already finalized.

## Message pillars

### 1. Durable memory

Useful project work should leave reusable knowledge behind.

### 2. Local ownership

Customer memory and project context remain under the user’s control.

### 3. Human review

People decide what becomes trusted memory and which actions are approved.

### 4. Familiar AI interfaces

AI should work with real project context without forcing users into a vague or fully autonomous system.

### 5. Honest product boundaries

ProChat has two products. Future capabilities are not presented as current offers.

## Tone

Communication should remain:

- calm;
- practical;
- precise;
- direct;
- evidence-aware;
- technically credible;
- honest about the beta stage.

Avoid:

- hype;
- autonomous-employee language;
- broad AI-transformation claims;
- absolute performance or cost claims;
- speculative product names;
- architecture before user value.
