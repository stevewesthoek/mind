## Current products

```text
ProChat Memory
ProChat Workbench
```

ProChat Memory for QA is the first discipline-specific edition of the flagship product.

## Current business stage

ProChat is pre-revenue.

The current objective is validation, not maximizing sales:

```text
QA domain experience
→ selected beta testers
→ real usage
→ product improvement
→ trust and traction
→ licensing
→ monetization
```

Pricing, commercial packaging, and team licensing are not yet final.

## ProChat Memory for QA entry point

Primary user:

```text
individual QA tester
```

Future economic buyer:

```text
QA business or software company purchasing licenses for testers
```

Primary promise:

```text
Stop solving the same QA failure twice.
```

Beta offer:

```text
Use a local, Markdown-first QA memory workspace to preserve reviewed
lessons from test investigations and retrieve them during future work.
```

The product is available through a public sanitized repository. ProChat manually selects an invited feedback cohort while allowing organic GitHub discovery.

The beta is free, has no fixed end date, and keeps all customer memory local.

## QA beta proof

Show:

```text
failed test
→ relevant reviewed memory
→ evidence-aware investigation
→ human-approved lesson
→ better future investigation
```

Measure:

- successful installation;
- time to first useful memory;
- retrieval during later investigations;
- accepted and rejected memory suggestions;
- repeat usage;
- tester trust;
- tester-reported effort saved;
- referrals and testimonials.

## ProChat Workbench entry point

Primary users:

- developers;
- builders;
- technical founders;
- vibe coders.

Positioning:

```text
A ChatGPT-first local builder workbench.
```

Core proof:

```text
request
→ exact local context
→ guarded change
→ targeted validation
→ explicit Git action
```

Workbench can be presented as an alternative workflow to Cursor, Claude Code, and similar tools when users value the native ChatGPT experience, local control, exact context, and guarded execution.

Do not promise unlimited usage, zero hallucinations, universal cost savings, or complete replacement of every editor.

## Website rule

The main ProChat website shows exactly two product cards:

1. `ProChat Memory` — `Currently available for QA`
2. `ProChat Workbench` — `A ChatGPT-first local builder workbench`

## Current channels

Near-term traction should come from:

- direct QA work and professional credibility;
- personal network conversations;
- manually invited beta testers;
- GitHub discovery;
- practical QA memory demonstrations;
- Workbench demonstrations on real local projects;
- user feedback, case studies, and referrals.

## Monetization boundary

Do not invent pricing before repeated value and licensing boundaries are clear.

Future monetization may include individual and organization licenses, but the current strategy is to validate retained value first.
